# Preference-Safe Minimum-Coverage Top-N Recommendation

Code and experiment inventory for the manuscript *Preference-Safe
Minimum-Coverage Top-N Recommendation via Minimum-Cost Flow*, submitted to
*Computers & Operations Research*.

The repository follows the paper's computational pipeline:

1. preprocess predicted user-item scores and retain each user's top `alpha`
   fraction of eligible candidates;
2. solve the binary model with Gurobi or its integral LP relaxation;
3. solve the equivalent explicit minimum-cost-flow (MCF) network;
4. solve exactly with TPCAR, the implicit coverage-augmentation algorithm;
5. obtain fast approximate solutions with BGCR; and
6. reproduce coverage-target and candidate-retention sensitivity analyses.

## Repository map

| Directory | Contents |
| --- | --- |
| `src/preprocessing/` | score loading, masking, and candidate-cache construction |
| `src/gurobi/` | Gurobi binary and Gurobi-LP benchmark scripts |
| `src/mcf/` | explicit OR-Tools SimpleMinCostFlow experiments |
| `src/tpcar/` | exact implicit augmentation experiments |
| `src/bgcr/` | Numba implementation of the batched heuristic |
| `src/sensitivity/` | sensitivity to `D/|I^alpha|` and `alpha` |
| `legacy/` | original runners retained for result traceability |
| `paper/` | manuscript PDF and experiment-to-code crosswalk |

## Data

The experiments use Amazon 5-core Office Products (OP), Video Games (VG),
Toys and Games (TG), Sports and Outdoors (SO), and Yelp. Predicted scores are
generated by LETTER. Raw reviews and LETTER-generated score matrices are not
committed because the matrices are very large and redistribution may be
governed by their source licenses.

Place score files under `data/raw/<dataset>/` and copy
`config/datasets.example.yaml` to `config/datasets.yaml`. Update paths and
shapes to match the locally generated matrices. Never commit private data,
credentials, or a Gurobi license file.

## Environment

Python 3.11 is recommended.

```bash
python -m venv .venv
.venv/Scripts/activate
python -m pip install -r requirements.txt
```

Gurobi experiments additionally require a licensed Gurobi installation and
its matching `gurobipy` package. TPCAR's fastest runner also requires the
compiled `tpcar_core_fast` extension described in `src/tpcar/README.md`.

## Experimental protocol

The paper uses `alpha=0.40`, `N=10`, and nominal coverage ratios
`0, 20, 40, 60, 80, 100%` for algorithm comparisons. List-length experiments
use `N in {10, 15, 20, 25, 30}`. Retention sensitivity uses
`alpha in {0.1, 0.2, ..., 1.0}`. Candidate construction and cache writing are
excluded from solver runtime, consistent with the manuscript.

The scripts in `legacy/` are the exact runners used for reported tables and
figures. They retain historical output schemas and some original absolute
paths. Organized copies under `src/` are grouped by method; replace their
paths with entries from `config/datasets.yaml` before large reruns.

## Reproducibility status

OP provides the complete independent exactness benchmark across Gurobi,
Gurobi-LP, MCF, and TPCAR. Large-instance dashes in the manuscript are genuine
time or memory limits, not missing runs.

For archival publication, create a tagged release and deposit that release,
small result tables, environment metadata, and checksums for externally hosted
score matrices in a persistent repository such as Zenodo, Mendeley Data, or
Code Ocean. A mutable GitHub branch alone is not a stable research artifact.
