  F 保留逐次最短增广的精确框架。每轮增加一个覆盖物品；通过压缩供给端和终点、复用最短路树、精确查
  询修复边界，减少重复计算。本文档与附带代码按实际实现逐项对应。


 问题、目标与输入
 给定候选边集 E、预测得分 Rui、每位用户的推荐数量 N，以及最低覆盖要求 D。每个用户必须选择 N 个不同
 候选物品，目标是在总覆盖不少于 D 的条件下最大化总得分。候选过滤在调用前完成。




   记号                     含义


   U、I、E                  分别指用户集合、物品集合和候选边集合；n=|U|，m=|I|，M=|E|。


   K0、K、D                 初始 Top-N 覆盖量、当前覆盖量、请求的最低覆盖量。


   d(v)、π(v)              d(v) 是可达核心节点的精确最短距离；π 是重标权用的势。首次搜索后，可达核心节点上 π=d。


   A、δ(v)                 A 是本轮失效子树并集；δ(v) 是局部 Dijkstra 算出的距离修正量。



 四个模块如何分工

   模块                     主要保留或压缩的内容


   局部修复                   保留有效树路径及距离，只重新计算失效子树。


   精确边界堆                  复用每个物品的候选列结构，查询区外进入修复区的最佳边。


   供给端聚合                  每个用户保留最低撤出费用及其实现边；等费用换来源时保留源树边。


   终点聚合                   每个用户保留最佳未覆盖候选，用全局堆选择下一条增广路径。


 F 是本轮实验使用的版本标签。本文给出实现解释、正确性论证要点和可复现入口；不据此宣称已建立新的最坏情况复杂度阶数。

 02 初始化与供给端聚合
 步骤 1：Top-N 初始解与单调状态
 每个用户的候选行按得分降序、物品编号升序排列，取前 N 个。若 K0≥D，独立 Top-N 已经满足约束，直接
 返回。否则，将物品分为三类：



 B 是供给集合，S 是单覆盖中转集合，Z 是未覆盖终点集合。规范增广路从 B 出发，经 S 中转，到 Z 结束。起
 点计数减 1，终点计数从 0 变 1，中间物品计数不变。因此 B、Z 只缩小，S 只扩大。单覆盖物品的推荐用户
 可以改变。

 步骤 2：每个用户压缩成一个供给入口



 au 表示用户 u 撤掉一个供给推荐的最小损失。将所有 s→供给物品→u 的选择压缩成一条 s→u，费用为 au；
 另存达到最小值的具体物品/边，用于恢复真实交换路径。

 实现：把用户初始选中的供给边按得分升序放入有序池，用指针跳过不再选中或失去供给资格的条目。在规
 范增广下，不会新增指向仍是供给物品的已选边，因此初始池足够；供给指针全程只前进。

 步骤 3：建立核心图，完整计算一次最短路树

   核心弧                存在条件                        原始费用


   s→u                用户有供给入口                     +au


   u→i                i∈S，候选边当前未选中                -Rui


   i→u                i∈S，u 是其唯一当前推荐用户            +Rui


 删除推荐记正费用，增加推荐记负费用。不能把这些原始负边直接交给普通 Dijkstra。初始化 π(s)=π(i)=0，
 π(u) 为用户初始已选推荐的最低分，然后用约化费用搜索：



 首次 Dijkstra 在整个可达核心图上执行，修正势并建立精确最短路树，保存父节点、实现边和子节点链表。未
 覆盖物品尚不放入核心树，供给物品由源弧隐式代表。后续只进行局部修复。

 03 终点聚合与最优增广
 步骤 4：每个用户只保留最佳未覆盖终点



 为可达用户 u 保存最佳未覆盖物品 zu，以及完整路径费用 qu。全局终点堆每个用户最多一个条目，实际排序
 键为（费用、物品编号、用户编号）。没有未覆盖候选的用户不入堆。

 候选行已按得分降序排列，用户指针指向第一个未覆盖物品。由于 Z 只缩小，指针永不回退。查询时核实堆
 顶：跳过已覆盖候选；更新过期距离/键值；重新入堆；直到堆顶条目与当前状态一致。不可达用户或耗尽候
 选的用户退出终点堆。



 旧键是当前键的下界。如果最小缓存键已经核实，它不大于其他缓存下界，也不大于其他真实键，因此得到
 精确最小值。d(u) 包含经过多个用户的最优交换前缀，不等于仅看该用户的一步撤出费用 au。

 步骤 5：恢复真实路径并执行交换
 选出 u*、z* 后，仅把获胜的未覆盖物品临时接到树上，设置 π(z*)=d(u*)-Ru*z*。从终点沿父指针回溯到源点
 ，利用供给入口的实现边恢复起点物品。沿路交替加入和撤掉推荐，每个用户的 N 个位置保持不变，覆盖增
 加 1。

   用户               A 的得分         B 的得分   C 的得分         初始选择


   u0               5.0           4.9     0.0           A


   u1               5.2           0.0     0.0           A


   u2               0.0           4.8     4.7           B


 例：N=1、D=3。A 是供给物品，B 单覆盖，C 未覆盖。路径 A→u0→B→u2→C 使 u0 从 A 换为 B，u2 从 B 换
 为 C，u1 保留 A。



 这一次增广包含两次用户推荐替换，覆盖从 2 变 3。到达 D 后立即返回，不再为下一轮维护树。这个例子已
 包含在代码的运行示例和验证脚本中。

 04 更新供给入口与精确边界查询
 步骤 6：找出真正需要修复的区域
 一次增广后，最多刷新两个用户的供给池：撤掉起点供给推荐的用户；以及当起点从两次推荐降为一次时，
 其剩下的推荐用户。后者的这条推荐也失去了供给资格。


  若供给的实现边变了，但最低费用 au 相同，就只替换实现边记录，保留相应的源树弧。若费用增加或入口
  消失，且该源弧属于最短路树，才将其后代纳入修复。


 增广路径上被删除/反向的内部树弧会使相应子树失效；供给费用变化还可能使另一棵源子树失效。合并这些
 根的后代，形成 A。修复区不只包含路径节点，也包含树上的非路径后代。实现按受影响根收集后代并去重。

 新覆盖终点加入单覆盖核心图；起点若从 2 次降到 1 次，也加入核心图。因此每轮最多新增两个单覆盖物品。
 新终点保留刚求得的路径费用作为初始势，新转为单覆盖的供给物品初始势设为 0。

 步骤 7：从区外给区内节点提供精确入口
 对于 A 内单覆盖物品 i，令 Uiout 为区外、可达且通过未选候选边连接 i 的用户集合，需要查询：




 每个物品维护一个持久的边界堆，第一次查询该物品时才读取整列候选并建堆。条目的缓存键为 d(u)-Rui。后
 续查询复用同一个堆：

 ① 堆顶来自修复区内部、不可达用户或当前已选边时，暂时取出。
 ② 堆顶合法但键值过期时，用当前 d(u) 刷新并调整堆。
 ③ 第一个合法且已核实的堆顶就是精确最小入口。
 ④ 将本次暂时取出的条目恢复；修复区和选边状态以后还可能变化。

 这里同样利用用户距离不下降，使缓存键成为下界。查询覆盖所有候选；没有固定保留前 k 条边的截断。每
 个物品只需一个最佳区外入口，就足以作为局部最短路的初始边界。

 对于 A 内用户 u，还要检查源弧 s→u，以及其来自区外单覆盖物品的已选反向边。后者只需查看该用户当前
 N 个推荐位置。边界堆主要处理“用户→物品”这一类密集候选边。

 05 局部 Dijkstra 与完整伪代码
 步骤 8：保留区外距离，只修复区内距离
 区外有效树路径不变。对于每条区外 a→区内 v 的候选边界，用旧势把入口转换成非负修正距离：



 以这些入口作多源种子，在 A 内按约化费用执行 Dijkstra。对成功到达的节点，更新势和父子关系；对无法到
 达的节点，标记为不可达。



 更新后，可达核心节点上的势再次等于精确最短距离。终点堆和边界堆不用逐条立即更新，下一次查询时按
 下界规则刷新。随后回到终点查询，开始下一轮。

 与实际主循环对应的伪代码

  F(E, R, N, D):
    x <- independent Top-N; count items; K <- coverage(x)
    if K >= D: return x
    build source pools; initialize feasible potentials
    build compressed core and one full shortest-path tree
    build terminal pointers and one terminal heap entry/user
    while K < D:
      (u, z) <- exact_lazy_terminal_query()
      if no terminal: return x, maximum-coverage certificate
      P <- recover_tree_path_and_source_witness(u, z)
      augment(P); update selections, counts, score; K <- K+1
      if K >= D: return x
      refresh at most two source pools
      preserve source-tree arcs when their costs are unchanged
      A <- invalid subtrees plus newly singleton item nodes
      seed A using exact boundary queries and other arc types
      run reduced-cost Dijkstra restricted to A
      update potentials, reachability, and the affected tree
    return x



   结构                             职责


   全局终点堆                          选下一条完整增广路径的终点。


   每个物品的边界堆                       为局部修复寻找区外进入区内的最便宜入口。


   Dijkstra 距离堆                   按距离修正量推进首次搜索或区内搜索。


 如果终点堆耗尽，表示已不存在增加覆盖的路径。当前覆盖是最大可实现覆盖；返回其得分最优解，并标记请求目标不可行。

 06 精确性依据与证明链条
 以下论证针对精确算术，并依赖原 TPCAR 最短增广框架的最优性不变量：每轮开始时，当前解在当前覆盖水
 平上得分最优。F 的任务是保持相同的精确最短路选择与增广语义。

 1. 规范路径与供给聚合保留最优增广
 若某条增广路径内部再次经过供给物品，那么到达该物品的前缀是保持覆盖量的可行交换。当前覆盖最优性
 排除了负损失前缀。删去此前缀、从最后一个供给物品出发，不增加路径费用。因此存在内部仅含单覆盖物
 品的最优增广路。

 对固定的首个用户，所有供给入口后接相同核心后缀，所以只需保留最小入口费用 au 及实现边。池中条目只
 失效、不新增，源指针维护不会漏掉更便宜的合法供给。

 2. 终点聚合保留全局最优终点
 对固定用户，所有未覆盖终点共享前缀距离 d(u)，故最佳终点必定最大化 Rui。在每个用户的这一最优候选中
 再取最小 qu，与枚举所有可达用户及未覆盖终点等价。

 3. 势与状态单调性支持懒更新
 最短路径上反向的新弧具有零约化费用；源弧费用只增加；新终点和新单覆盖起点的势按前述规则设置，保
 持所需约化费用非负。后续修正距离非负，所以原有可达用户的势不下降。Z 缩小使最佳终点评分不增加。

 用户可达集合不会扩张：新增反向弧只连接本轮原已可达的路径节点；新增单覆盖物品的出弧也通向原已可
 达用户。因此退出终点堆的不可达用户无需重新加入。此性质与仅仅“距离单调”是两个需要分别说明的不变量。

 4. 下界堆查询是精确查询
 设所有合法条目的缓存键不大于当前真实键。取最小缓存键并核实：若过期则更新重排；若已准确，它不大
 于任何其他缓存键，继而不大于任何其他真实键。边界查询暂时移除不合法条目，使同一推理适用于本次合
 法边集合。

 5. 局部修复保持完整最短路信息
 区外旧树路径仍存在，给出原距离的可达上界；可行势排除更短的新路径，所以区外距离仍精确。任何到达
 区内的路径，都可按最后一次从区外进入区内的位置分解。精确边界种子覆盖这些入口，区内 Dijkstra 求出其
 最佳后缀。因此修复后的树仍给出全局最短距离。

 6. 增广与终止保持原优化目标
 F 每轮执行的是精确最短增广，故沿用原框架的最优性归纳。达到 D 时返回目标最优解；若无增广路，返回最
 大覆盖下的得分最优解。代码另将压缩可达集映回原残量图，检查供给点全在集内、残量出弧闭合且没有可
 达未覆盖物品，从而独立认证无法继续增加覆盖。

 闭集证书认证最大覆盖，不能单独认证得分最优。得分最优由上述增广不变量保证，数值实验另以独立 LP 上界核对。正式论文
 应展开相关引理的假设与证明，并说明浮点误差处理。

 07 复杂度：可以证明什么
 记 n=|U|、m=|I|、M=|E|、实际增广次数 L。若目标可行且 D>K0，则 L=D-K0；不可行时 L=Kmax-K0。F 仍
 然逐次增加一个覆盖物品，没有把 L 轮增广合并成一次。

   部分                       可直接说明的累计代价或上界


   候选排序与双向 CSR              属于预处理。按用户行排序可写为 O(Σu deg(u) log(deg(u)+1))；代码通用边表入口采用全局
                            字典序排序。


   供给池                      每个用户最多 N 条初始供给边；排序 O(nN log(N+1))，全部源指针前进次数≤nN，每轮最
                            多两个用户需要刷新。


   终点指针                     每条用户候选行的指针只前进，全部前进次数≤M；这不包括终点堆的重复键刷新。


   边界堆初建                    每个物品最多建堆一次；总初建条目≤M。每次查询仍可能刷新、暂时排除并恢复很多条目。


   局部修复                     工作量取决于失效子树大小和涉及用户的候选行长度；单轮可能接近全图。



 建议使用分项、实例相关的复杂度表达



 若 Ht 为终点键刷新次数、Qt 为终点查询次数，则终点维护可界为 O(M+(n+Qt+Ht)log(n+1))。供给维护还包括
 每轮常数次刷新、指针累计推进及增广路径恢复。

 若 Qb 为边界查询次数，Hb 为键刷新次数，Xb 为临时排除次数，则边界维护可界为
 O(M+(Qb+Hb+Xb)log(n+1))；恢复条目的成本已计入 Xb 项。

 对于第 r 轮，令 Wr 为区内搜索及非堆边界处理实际检查的邻接条目数，Ar 为修复节点集。采用代码中的二叉
 堆，可用 O((|Ar|+Wr)log(n+m+M+2)) 给出保守的局部搜索上界，再对所有轮次求和。

 空间与当前实现边界
 计入双向候选索引、选择状态、树、供给池、边界堆和历史记录，空间可写为 O(M+nN+n+m+L)。每个物品
 的边界堆常驻后会额外保存其候选列条目，因此少读边不等于常数额外内存。


  当前 F 不启用单覆盖候选激活索引，也不启用候选交集索引。展开一个修复用户时，仍扫描其完整原始候
  选行，再筛选修复区内物品。可以证明的是若干维护结构的累计界；不能把整个算法写成“每条边总共只读
  一次”或 O(M)。

 此前 9 次运行共核对 59,913 个轨迹目标值，与旧基线的最大差为 0；9 个最大覆盖闭集证书均通过。该数据上的提速不能替代一
 般复杂度分析。
