# BGCR排序与单次扫描策略比较

这组实验补充COR审稿意见所要求的“无初始损失排序扫描”与“每步当前最小损失替换”对照。它与已有的BGCR-D模块消融分开统计，不修改TPCAR，不启动旧版TPCAR或V0。

## PyCharm入口

打开项目 `E:/PythonProject`，解释器使用 `E:/PythonProject/.venv/Scripts/python.exe`。

| 运行配置 | 用途 |
| --- | --- |
| BGCR-STRATEGY-ALL | OP、Yelp、SO全部设置，最多66次 |
| BGCR-STRATEGY-OP | OP，共22次 |
| BGCR-STRATEGY-YELP | Yelp，共22次 |
| BGCR-STRATEGY-SO | SO，共22次 |
| BGCR-STRATEGY-RESUME | 续跑全部数据集的缺失任务 |
| BGCR-STRATEGY-PLOT | 等结果完成后，生成4张图、9份三线表及PDF |
| BGCR-FIG-F21至BGCR-FIG-F24 | 只重画对应单图，不运行算法 |

已完成且通过输入核对的任务会复用。请勿为了重画图点击实验入口，也不要同时启动多个数据集入口；统一锁会使它们顺序运行。断网不会中断本地程序；电脑必须保持开机且不睡眠。

## 五个版本

| 标记 | 原生模式 | 选择策略 | 实现 |
| --- | --- | --- | --- |
| R | random_source | 初始未覆盖物品随机排列一次，逐个访问 | 供给聚合 |
| A | original | 按初始损失固定排序，单次扫描 | 原始N槽位供给查询 |
| B | fixed_source | 与A相同 | 供给聚合 |
| C | dynamic_item_heap | 每步选当前全局最小损失可行直接替换 | 供给聚合＋物品堆 |
| D | dynamic_user_heap | 与C相同 | 供给/终端聚合＋用户堆 |

R只随机化访问物品的先后次序。对每个被访问物品，仍选当前最小损失的可行替换；不随机选用户或供给槽位。固定种子为2026101901至2026101910，保存在每个任务和结果中。相同二进制及标准库下可重现；不承诺跨编译器shuffle序列相同。

R/B评价初始损失排序；A/B评价供给查询加速；B/C评价固定单次扫描与动态选择；C/D评价保持动态规则时的数据结构差异。C/D同时涉及用户堆及终端聚合，不能把它们的时间差全部归于单个模块。已有D版的逐项关闭模块实验仍用于单独评价这些结构。

## 相同接口与统计规则

- 数据集：OP、Yelp、SO。N=10，D为候选并集C。R运行10个种子，A/B/C/D各3次独立进程，共66次。
- 同一数据集共享graph_id、候选集、Top-N初始解、整数评分和D。评分按rint(score×1e6)取整，使用ties-to-even。
- 前3个区组随机交错5个版本，之后完成其余R种子。没有清空OS缓存，也没有跨批挑选最快值。
- 每次审计合法性、推荐长度、整数评分和覆盖；未达到目标时还检查直接替换邻域是否已耗尽。
- A/B及C/D逐项核对交换事件相同。R/B策略不同，允许终止覆盖和评分不同。
- 时间同时保留构建、核心、完整计量与导出；方法所需逆向CSR真实构建。OS峰值工作集、私有内存采样和工作量计数均保留。
- 质量差距对齐每次实际达到的K，与新版精确TPCAR轨迹在同一K处比较。不能要求不同选择策略的终点整数目标相同，也不能把BGCR未达到目标说成全局不可行。
- 图示原始点、中位数和最小至最大范围；表格另给均值和样本标准差。R的波动包含种子差异及计时波动，确定性重复只反映计时波动。没有进行显著性推断。
- 原有ID顺序的9次结果单列为历史参照，未加入本次66次样本。
