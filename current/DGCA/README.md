# BGCR-D：与新版TPCAR统一接口的本地实验

项目：`E:/PythonProject/BGCR_D`。桌面`BGCR_D`快捷方式指向此目录。PyCharm继续使用`E:/PythonProject`项目及其既有`.venv`解释器。

## 运行入口

- `BGCR-OP`、`BGCR-YELP`、`BGCR-TG`、`BGCR-VG`、`BGCR-SO`：对应数据集，默认N=10、最高覆盖请求、独立运行一次。可加`--n 15`、`--repeats 3`、`--percentages 0 20 40 60 80 100`。
- `BGCR-ALL-COMPARE`：正式完整批次；已排队，等待TPCAR第二批消融结束后自动开始。
- `BGCR-RESUME`：协议不变时复用已完成结果，继续完整批次。它明确清除旧停止请求；运行前先确认没有旧实验进程。
- `BGCR-PLOT`：等待BGCR完整批次完成，再生成联合图表工作稿。

不要在队列运行中重复启动单图配置。所有正式求解共用TPCAR的进程锁，防止争用内存。`TRMNL-STOP-COMPARE`是共用停止入口：若TPCAR还在运行，会停止当前TPCAR并阻止后续BGCR越过它启动。

## 输入相同意味着什么

直接读取`TRMNL_BENCH/data/<dataset>/ready.json`所指定的不可变候选图。不运行压缩包里的下载或重新筛选脚本，不复用其中跨机器的计时结果。

- 候选边、用户/物品ID、每用户候选集合、排除已知对规则，与TPCAR完全一致。
- 同一N、同一覆盖下限D、同一初始Top-N、同一行内排序与同分规则。
- 统一整数评分`q=np.rint(float64(original_score)*1e6)`，优化使用可精确表示整数的float64；不转回float32。
- 同时保存整数目标值、取整APS和原评分重算APS。排序按q降序、物品编号升序。

初始Top-N的覆盖与整数目标必须完全一致，输入不一致立即停止。最终BGCR是启发式，不要求其目标值等于精确TPCAR；不能为了输出一致而改目标、覆盖或候选边。

每次结束重新检查推荐数、用户候选成员、重复物品、覆盖和整数总分；无法达到D时核查直接替换邻域耗尽。状态为`FEASIBLE`或`TARGET_UNREACHED`，不将启发式失败写成原问题`INFEASIBLE`。

输出还读取相同图、相同N的精确TPCAR轨迹，核对并记录**相同实际覆盖K下**的精确评分上界及差距。不同覆盖的评分不直接混作同一问题的最优性差距。Yelp的BGCR终点不是Kmax。

## 正式批次

输出：`outputs/BGCR_matched_TPCAR_20261018`。

| 阶段 | 配置与次数 |
| --- | --- |
| 主比较 | 五图，N=10，六档覆盖要求，每档3次，共90次 |
| 不同N | 五图，N=15、20、25、30，D=C，各1次，共20次 |
| 模块消融 | 五图，N=10、D=C，完整配置及三个关闭模块配置，各3次；完整配置15次复用本批主比较，因此新增45次 |
| 同邻域对照 | OP、Yelp、SO，固定初始损失排序与物品ID未排序扫描，各3次，新增18次 |

最大实际计划173次；模块消融图里完整的60个运行点包含复用的15次主比较。资源受限时按既定协议只尝试一次，跳过相同设置的后续重复。主比较D=ceil(p*C/100)，p依次100、80、60、40、20、0，C取当前候选并集物品数，与TPCAR相同。

没有开启TPCAR的Yelp近边界、K0+1、候选比例敏感性或旧版TPCAR实验。BGCR的N>10结果应称启发式覆盖及评分结果，不称原问题的精确解。

## 四个模块配置及两个对照

| 原生模式 | 含义 |
| --- | --- |
| dynamic_user_heap | 原包D版：供给端聚合、终点指针、全局用户惰性堆 |
| dynamic_user_heap_nosource | 关闭供给池指针，查询时扫描用户当前N个槽位；保留终点指针和用户堆 |
| dynamic_user_heap_noterminal | 关闭终点指针复用，查询时从行首精确扫描；保留供给聚合和用户堆 |
| dynamic_user_scan | 关闭全局用户堆，每步扫描所有用户取得当前最小直接替换；保留两端聚合 |
| fixed_source | 原包固定初始损失排序、单次扫描，带供给聚合 |
| id_source | 原包物品编号顺序、单次扫描，带供给聚合 |

前三个模块关闭版本仍每步精确选当前最小直接替换，与完整D版应保持同样的交换序列和评分；它们不改变为原问题的全局精确算法。固定排序和ID扫描是不同决策规则，评分与终点覆盖允许不同。它们是同直接替换邻域的对照，不与跨用户交换链的TPCAR混为一种邻域。

`supplied/`保留用户ZIP原样解压。`native/bgcr_d_bench.cpp`为独立适配副本，原文件未覆盖。只改模块接口、逆向权重按原边ID读取，并明确增加上述模块开关。D版只需要正向CSR，`solve_user`提供真实的正向输入入口，不传伪造的反向图。固定排序/ID对照确实需要反向查询，其反向CSR每次重新构造并计时。模块关闭本身不使用旧版TPCAR。

## 计时与内存

每次独立进程，使用与TPCAR相同的监控、0.2秒内存采样和资源限制：构建＋求解1800秒、私有字节12 GiB软守卫、系统可用内存连续5次低于1 GiB停止。没有声称设置OS硬内存配额。

分别记录共享输入读取、方法专用构造/验证、核心调用、审计、导出。主比较同时提供核心时间与构建＋求解时间；评分转换及模式所需反向CSR不能隐藏到共享预处理里。记录OS峰值工作集、采样私有内存；每次重建方法结构，不清空OS磁盘缓存。

关闭终点复用、关闭用户堆的配置可能很慢。达到预算如实记资源状态，不临时更换数据规模或目标，也不把它们记成问题不可行。

## 已完成验证

`validation/small_validation.json`：200个固定种子图、4128次调用；与原包2064次输出等价核查；动态D版及三个模块关闭版本逐步匹配独立穷举的当前最小直接替换；200个终止实例另与最大覆盖LP核对1/2覆盖界。覆盖同分、负分、取整连续评分、小N及15/20/25/30、零/正缺口、终止情形。

`validation/worker_pipeline_v2`：六个模式的独立进程、共享输入、审计、导出和资源监控链路通过小图检查。小图验证不计入正式实验，上传包中的历史结果也不计入本机正式批次。

验证支持接口和实现核查，不替代论文的理论证明，亦未将PDF中损失预算保证自动视为已完成独立证明审查。

原TPCAR两批实验及其制图程序保持原样继续，不重跑或覆盖已有结果。桌面快捷方式和PyCharm配置仅指向此项目，不复制第二套候选数据。

VG/TG扩展：TPCAR原队列完成后接续补跑，BGCR等待全部五图TPCAR消融结束。同邻域排序对照仍采用OP、Yelp、SO三个代表数据集。
