# 第二批：更大N的精确结果与新版TPCAR模块消融

本批只启动用户指定的两项工作，不启动Yelp近边界或K0+1补充请求；不运行旧版TPCAR或BGCR。

## 1. 更大N的精确结果

`run_exact_N.py` / PyCharm `TRMNL-EXACT-N-15-30`。

- OP、Yelp、TG、VG、SO；N=15、20、25、30；每次请求D等于当前固定候选图的物品并集C，共20个配置。
- 每个配置仅一次，用于补精确覆盖、目标值和APS，不把这些单次时间当成重复性能比较。
- 与第一批完全相同的候选图和整数化评分；同一个原始新版TPCAR后端。已检查五图每用户候选数均至少满足N=30，不扩充候选集。
- 同样记录构建、求解、校验、峰值内存、状态、增广轨迹和推荐列表。限制为构建＋求解1800秒、私有内存12 GiB软守卫、系统可用内存低于1 GiB连续五次保护停止。
- 请求可行且覆盖全集时，Kmax=C由上界直接确定。请求不可行时，需通过原残量网络闭集证书核查覆盖边界。证书只认证覆盖；评分精确性依赖算法正确性与独立核对，不用证书单独声称评分最优。
- 输出：`outputs/second_batch_N_exact_20261018/N15`、N20、N25、N30。整批结束汇总`exact_N_results.csv/json`。

## 2. 新版模块消融

`run_ablation.py` / PyCharm `TRMNL-ABLATION`。排在N批次之后，串行运行。

| 模式 | 含义 |
| --- | --- |
| state_source | 完整新版，源端聚合、终点聚合、精确边界堆均开启 |
| state_terminal | 关闭源端聚合，保留终点聚合与边界堆 |
| state_source_only | 关闭终点聚合，保留源端聚合与边界堆 |
| state_source_noheap | 保留源端、终点聚合，关闭边界堆，精确扫描相应物品列 |

四种配置均保留精确增广和局部最短路树修复。不据此消融声称“关闭局部修复”的收益。

- OP、Yelp、SO，N=10，D=C；四种配置各3次，最多36次。资源限制的设置只尝试一次，跳过该配置其余重复。
- 三次用于比较时间波动。完整配置也在同一个消融二进制下重新跑，不混入第一批不同二进制的时间。
- 每次重建方法结构；构建和求解分别计时，报告合计；同一候选集、目标、取整规则、线程和资源守卫。
- Yelp最高请求不可行，四种配置比较的是同一个“尝试最高请求并返回边界”的任务；不拿该任务的时间与固定可行目标混算加速比。
- 记录目标值、覆盖、证书、时间、内存、修复区大小、候选扫描、边界堆、源端与终点维护计数。
- 输出：`outputs/second_batch_ablation_20261018`，包含`ablation_results.csv`、`checks.json`、逐次日志、内存及轨迹。

实现隔离：`native_ablation`和`state_variants_ablation`为单独编译的副本。只新增“源端聚合开启且边界堆关闭”的组合；其查询退回已有的精确列扫描分支。原TRMNL_F、主比较源码、主比较二进制及第一批结果均未覆盖。`second_supervisor.py`沿用原进程监控，仅增加显式选择消融worker；`ablation_worker.py`将当前模式传给独立后端，继续复用已核查的输入组装和结果审计。

预运行验证：200个固定种子小图、2076次四变体调用与独立HiGHS LP核对，其中1600可行、476不可行，整数目标误差0；完整配置另与第一批后端做519次目标值、选边及关键计数等价核查。另通过四模式独立进程和资源监控链路检查。见`validation/ablation_20261018/validation.json`及`validation/ablation_worker_pipeline/validation.json`。
